## Exact desktop/manual QA after deployment
1. Confirm header shows v0.8.1. Open the landing page. Question should be centered over orbiting historical card *faces* on dark starfield. Some cards should pass close to the viewpoint.
2. Enter a question (3–600 chars). Start Divination. Verify cards visibly converge before showing a jumbled circular shuffle. Try immediately pressing Finish Shuffling: it must be disabled for at least 5 seconds after actual shuffle starts; by about 7–8 seconds total it should become enabled, with a settled deck visible.
3. Press Finish Shuffling; deck should burst into existing 3D sphere (2D fallback for unavailable WebGL2). Rotate and pick one card. It should glow yet remain in the sphere. Click it again, or tap Undo beneath its slot; it disappears from the selection, not from the actual deck. Repeat and pick exactly three.
4. Confirm button must be disabled for 0, 1, or 2 cards. At 3, click exactly once; see a black-hole pull on unselected cards and three selected backs align into 01 Past, 02 Present, 03 Future. Repeat-click attempts should not duplicate the lock.
5. Reveal all three slowly using existing drag/side/pinch/keyboard controls. Verify position labels, upright/reversed, authentic illustrated faces, and that the v0.7 cinematic reading works. Local Exodia only when on local port 4173.
6. Inspect Chinese deck dialog: private local images still import; a future custom Chinese deck must not be publicly selectable without 78 originals.
7. Mobile 320px / 375px, Windows Chrome, iOS Safari, Android Chrome: check keyboard, starfield perf, no overflow or clipped CTA, page/tab suspend and reduced-motion users (instant transitions/flat 2D).
8. Do NOT equate external marketing screenshots with deployed source. Ensure no licensed Chinese Tarot scans were added to the public build.

## Open issues / gating decisions
- Device-side GPU and browser visual QA is still needed; CI tests alone do not prove frame rate, exact aura shading, card face legibility or black-hole feel.
- v0.8.1 uses lightweight CSS/WebGL effects for its transition. Artistic polish and Artemis divination table are Phase 8.2.
- Session state reducer is authoritative for ritual gates; the numeric step UI remains a compatibility projection until the full 8.2/8.3 conversion.
- SQL reference is NOT applied. Authentication, authorization policies, consent/export/delete and storage provider decisions are Phase 8.5 gates.
- Stage 1 is local preflight; Stage 2 AI will start on locked trio only once structured response contracts are implemented in Phase 8.3. The v0.7.1 Exodia text adapter is kept opt-in and separate.
